如何写博文

文件开头被两个 --- 包住的部分叫 front-matter，用来写文章的元信息。

正确格式

各字段说明

字段 说明 是否必填
title 文章标题 建议填
date 发布时间，决定排序 建议填
tags 标签，方括号数组 选填
categories 分类，方括号数组 选填
description 摘要，用于首页卡片和搜索引擎 选填
cover 封面图，如 /img/cover.jpg 选填
top 设为 true 则置顶 选填

五个必须遵守的规则

  1. 冒号后必须有一个空格 —— title: 我的博客
  2. 标签用方括号包裹 —— tags: [随笔, 学习]
  3. 多个标签用英文逗号分隔 —— [随笔, 学习]
  4. --- 必须单独占一行，且是第一行（前面不能有空行）
  5. 不要用 Tab 缩进，YAML 只认空格

完整写作流程

第 1 步：新建文章

会在 source\_posts\ 下生成 文章标题.md，并自动填好 front-matter 框架。

也可以手动在 E:\博客\myblog\source\_posts\ 里新建 .md 文件，效果一样。

第 2 步：写内容

用 VS Code 打开编辑。注意遵守第二节的五条规则，特别是冒号后要有空格。

第 3 步：本地预览（推荐）

浏览器打开 http://localhost:4000 查看效果。按 Ctrl + C 停止。

如果 front-matter 写错了，这一步就会报错并告诉你第几行——不用等到推送后才发现。

第 4 步：发布

推送后 GitHub Actions 自动构建部署，约 30 秒完成，再过 1～2 分钟 Pages 的 CDN 刷新。

查看构建进度：https://github.com/sunday103/sunday103.github.io/actions

命令速查

操作 命令
新建文章 npx hexo new "标题"
新建独立页面 npx hexo new page about
本地预览 npx hexo server
发布 git add -A; git commit -m "..."; git push
看构建日志 打开仓库的 Actions 页面

**不要再使用 npx hexo deploy**。改造后由 GitHub Actions 负责发布，本地 hexo d 会和它争抢 main 分支。

Markdown 常用语法速查

Butterfly 主题额外支持的功能：

功能 写法
提示框 {% note info %} 内容 {% endnote %}
标签页 {% tabs %} 系列
折叠块 {% folding %} 内容 {% endfolding %}
数学公式 front-matter 加 mathjax: true，正文用 $公式$

注意：嵌套代码块时，Markdown 里需要用四个反引号包裹三个反引号的代码块。

常见问题

症状 原因 解决
构建报 front-matter 错误 格式写错 按报错提示的行号修正
文章没出现在网站上 格式错被跳过 / 忘了 push 看构建输出有没有校验错误；确认 git push 成功
推送后网页没变化 Actions 还在跑 / CDN 缓存 看 Actions 页面，等 1～2 分钟
中文变乱码 文件编码被破坏 用 VS Code 重新保存为 UTF-8
URL 里中文变一长串 %E4%B8%AD URL 编码，正常现象 需要短链接可装 hexo-abbrlink
标签页点进去是空的 文章没写 tags 在 front-matter 加 tags: [标签名]
